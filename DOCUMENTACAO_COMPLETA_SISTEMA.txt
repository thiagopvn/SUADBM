1. VISÃO GERAL DO SISTEMA
================================================================================

1.1 PROPÓSITO
O SUAD CBMERJ é um sistema de controle financeiro e orçamentário desenvolvido para 
gerenciar créditos, despesas, prestações de contas e rastreamento de processos SEI,
notas de empenho e ordens bancárias da Superintendência Administrativa do CBMERJ.

1.2 TECNOLOGIAS UTILIZADAS
- Framework: Next.js 15 com App Router
- Linguagem: TypeScript com modo strict
- Banco de Dados: Firebase Realtime Database
- Estilização: Tailwind CSS
- Gráficos: Recharts
- Gerenciamento de Estado: React Hooks + Firebase listeners em tempo real
- Runtime: React 19 / Node.js

1.3 ARQUITETURA
O sistema segue uma arquitetura de componentes React com:
- Separação clara entre lógica de negócio e apresentação
- Padrão de hooks customizados para gerenciamento de estado
- Serviço singleton para operações Firebase
- Sistema de tipos TypeScript para garantir integridade dos dados

3. MODELO DE DADOS
================================================================================

3.1 ENTIDADES PRINCIPAIS

3.1.1 CREDITO
Interface: Credito
Descrição: Representa um crédito orçamentário
Campos:
- id: string - Identificador único
- creditoCodigo: string - Código do crédito
- anoExercicio: number - Ano de exercício
- eixos: string[] - Array de eixos (VPS, ECV, etc.)
- valorGlobal: number - Valor total do crédito
- origem: OrigemCredito - Rastreabilidade da origem
- natureza: string - Natureza do crédito
- dataLancamento: string - Data de lançamento (YYYY-MM-DD)

3.1.2 DESPESA
Interface: Despesa
Descrição: Representa uma despesa independente
Campos:
- id: string - Identificador único
- objeto: string - Descrição do objeto
- processoSEI: string - Número do processo SEI
- status: 'Planejado' | 'Empenhado' | 'Liquidado' | 'Pago' | 'Cancelado'
- fontesDeRecurso: FonteDeRecurso[] - Array de fontes de financiamento
- valorTotal: number - Valor total (soma das fontes)
- dataPrestacaoContas: string | null
- prestacaoContasInfo: string | null
- metaAssociada: string - Meta associada
- acaoAssociada: string - Ação associada

3.1.3 FONTE DE RECURSO
Interface: FonteDeRecurso
Descrição: Vincula despesas a créditos com detalhes transacionais
Campos:
- id: string - Identificador único
- creditoId: string - ID do crédito associado
- valorUtilizado: number - Valor utilizado desta fonte
- notaEmpenho?: string - Número da nota de empenho
- dataEmpenho?: string - Data do empenho
- ordemBancaria?: string - Número da ordem bancária
- dataPagamento?: string - Data do pagamento

3.1.4 PRESTAÇÃO DE CONTAS
Interface: PrestacaoContas
Descrição: Obrigação de prestação de contas
Campos:
- id: string - Identificador único
- creditoId: string - ID do crédito pai
- ano: number - Ano da prestação
- periodoLabel: string - Label do período
- prazoFinal: string - Data limite (YYYY-MM-DD)
- status: 'Pendente' | 'Em Atraso' | 'Entregue'
- dataEntrega?: string - Data de entrega
- processoSEI?: string - Processo SEI da prestação
- despesasVinculadas: string[] - IDs das despesas vinculadas
- observacoes?: string - Observações

3.1.5 META/AÇÃO
Interface: MetaAcao
Campos:
- descricao: string - Descrição da meta ou ação

3.1.6 FECHAMENTO ANUAL
Interface: FechamentoAnual
Campos:
- totalDevolvido: number - Total devolvido
- dataFechamento: string - Data do fechamento
- usuarioResponsavel: string - Usuário responsável

7.1 FIREBASE SERVICE
Arquivo: lib/firebase-service.ts
Padrão: Singleton
Métodos principais:

Créditos:
- getAllCreditos(): Retorna todos os créditos
- getCreditoById(id): Retorna crédito específico
- getCreditosWithCalculations(): Créditos com cálculos
- createCredito(credito): Cria novo crédito
- updateCredito(id, updates): Atualiza crédito
- deleteCredito(id): Remove crédito

Despesas:
- getAllDespesas(): Retorna todas as despesas
- getDespesaById(id): Retorna despesa específica
- getDespesasWithCredits(): Despesas com créditos associados
- createDespesa(despesa): Cria nova despesa
- updateDespesa(id, updates): Atualiza despesa
- deleteDespesa(id): Remove despesa

Prestações de Contas:
- getPrestacoesByCredito(creditoId): Prestações do crédito
- gerarPrimeiraObrigacao(creditoId, dataLancamento): Gera primeira obrigação
- gerarProximaObrigacao(prestacaoAnterior): Gera próxima obrigação
- marcarPrestacaoComoEntregue(id, data, processo): Marca como entregue

Dashboard e Busca:
- getDashboardData(year?): Dados agregados do dashboard
- searchDespesasByObjeto(termo): Busca despesas por objeto
- searchCreditosByCodigo(termo): Busca créditos por código
- searchByNotaEmpenho(termo): Busca por nota de empenho
- searchByOrdemBancaria(termo): Busca por ordem bancária

7.2 UTILITÁRIOS

- cn(...classes): Combina classes CSS (clsx + tailwind-merge)

9. FLUXOS DE NEGÓCIO
================================================================================

9.1 CICLO DE VIDA DO CRÉDITO
1. Criação do crédito com dados básicos
2. Geração automática da primeira prestação de contas
3. Associação de despesas ao crédito
4. Acompanhamento de utilização e saldo
5. Fechamento ao final do exercício

9.2 CICLO DE VIDA DA DESPESA
1. Criação com status "Planejado"
2. Definição de fontes de recurso (múltiplos créditos)
3. Empenho: adiciona nota de empenho e data
4. Liquidação: processa liquidação
5. Pagamento: adiciona ordem bancária e data
6. Vinculação a prestação de contas

9.3 CICLO DE PRESTAÇÃO DE CONTAS
1. Geração automática ao criar crédito
2. Período de 4 meses para preparação
3. Vinculação de despesas relacionadas
4. Entrega com processo SEI
5. Geração da próxima obrigação (se aplicável)

9.4 CÁLCULOS FINANCEIROS
Saldo Disponível do Crédito:
saldoDisponivel = valorGlobal - (valorEmpenhado + valorPago)

Valor Empenhado:
- Soma de fontesDeRecurso com notaEmpenho preenchida

Valor Pago:
- Soma de fontesDeRecurso com ordemBancaria preenchida

Valor Total da Despesa:
- Soma de todos os valores em fontesDeRecurso

================================================================================
10. REGRAS DE NEGÓCIO
================================================================================

10.1 VALIDAÇÕES DE CRÉDITO
- Código do crédito deve ser único
- Valor global deve ser positivo
- Ano de exercício válido (2020-2030)
- Data de lançamento obrigatória

10.2 VALIDAÇÕES DE DESPESA
- Processo SEI obrigatório
- Pelo menos uma fonte de recurso
- Valor total > 0
- Saldo disponível no crédito suficiente
- Status segue ordem: Planejado → Empenhado → Liquidado → Pago

10.3 REGRAS DE PRESTAÇÃO DE CONTAS
- Primeira obrigação: 4 meses após lançamento
- Obrigações subsequentes: 4 meses após anterior
- Status "Em Atraso": prazo vencido e não entregue
- Nova obrigação gerada ao marcar anterior como entregue

10.4 REGRAS DE EXCLUSÃO
- Crédito não pode ser excluído se tem despesas
- Despesa não pode ser excluída se vinculada a prestação entregue
- Prestação entregue não pode ser alterada
